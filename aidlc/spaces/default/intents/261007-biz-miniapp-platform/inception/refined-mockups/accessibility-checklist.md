# Accessibility Checklist

- One logical `h1` per screen; headings follow hierarchy.
- Semantic `header`, `nav`, `main`, `form`, `fieldset` and `table` landmarks.
- Every input has a visible label and validation text associated programmatically.
- Keyboard can reach every action; focus order follows visual order; focus is visible.
- Enter submits forms; duplicate submissions are prevented without trapping focus.
- Loading and result messages use an accessible live region.
- Errors and statuses include text, never color alone.
- Table headers, edit actions and responsive cards remain understandable without sighted pointer use.
- Review against WCAG 2.1 AA basics with keyboard-only pass, automated axe scan, and manual label/heading/status checks.
